# 数据库迁移手册

本手册用于部署 2026-10 电费台账、合同生效期和电表品牌合同关联改动。当前代码路径以 PostgreSQL、V5 数据结构为前提。迁移脚本只在仓库中准备好，**尚未在任何数据库执行**。数据库操作由维护人员在确认目标环境、完成备份后执行。

## 本次迁移文件及顺序

按以下顺序在同一个目标数据库执行。每个脚本需完整执行成功后再继续下一个：

1. [`2026_10_site_electricity_difference_split.sql`](../../backend/app/migrations/2026_10_site_electricity_difference_split.sql)：增加共享电表未分摊量字段，并明确损耗字段含义。可重复执行。
2. [`2026_10_contract_period_constraints.sql`](../../backend/app/migrations/2026_10_contract_period_constraints.sql)：替换合同生效区间排斥约束，允许不重叠的续约/调价合同。若发现历史重叠合同，脚本会报错中止；先处理历史数据，再重试。
3. [`2026_10_meter_brand_contract_link.sql`](../../backend/app/migrations/2026_10_meter_brand_contract_link.sql)：增加普通电表及共享分摊行的品牌合同关联，并仅为场地内恰好只有一份品牌合同的数据自动回填。多合同记录会留空，需在应用中人工选择。

不要把 `schema_sync.sql` 当作以上迁移的替代品；它不会执行这些有数据回填/约束变更的手工迁移。

## 执行前检查

1. 确认连接的是预期环境和数据库，确认数据库为 PostgreSQL，且已完成 V5 结构升级。迁移依赖 `landlord_monthly_elec`、`contracts`、`meters`、`meter_shared_allocations` 等表；合同排斥约束还依赖 `btree_gist` 扩展（V5 初始化脚本会创建）。
2. 在维护窗口前创建数据库备份，并确认备份文件可读、大小合理。示例命令中的连接参数应从本机安全配置读取，不要把密码写进命令历史或提交到仓库：

   ```bash
   pg_dump --format=custom --no-owner --file=before_2026_10.dump "$DATABASE_URL"
   pg_restore --list before_2026_10.dump
   ```

3. 记录当前应用版本、数据库名称、备份文件位置及迁移执行人。先在测试/预发布数据库按同样步骤演练。
4. 对合同迁移先运行下面的只读预检。查询结果必须为零行；若有记录，先核实并修正重叠合同区间，不要删除排斥约束检查或绕过异常继续部署。

   ```sql
   SELECT a.id AS contract_a, b.id AS contract_b,
          a.contract_type, a.landlord_id, a.brand_id, a.entity_id,
          a.start_date AS a_start, COALESCE(a.early_end_date, a.end_date) AS a_end,
          b.start_date AS b_start, COALESCE(b.early_end_date, b.end_date) AS b_end
   FROM contracts a
   JOIN contracts b ON a.id < b.id
   WHERE a.contract_type = b.contract_type
     AND a.landlord_id = b.landlord_id
     AND (a.contract_type = '场地合同'
          OR (a.brand_id IS NOT DISTINCT FROM b.brand_id
              AND a.entity_id IS NOT DISTINCT FROM b.entity_id))
     AND daterange(COALESCE(a.start_date, DATE '1970-01-01'),
                   COALESCE(a.early_end_date, a.end_date, DATE '9999-12-31'), '[]')
         && daterange(COALESCE(b.start_date, DATE '1970-01-01'),
                      COALESCE(b.early_end_date, b.end_date, DATE '9999-12-31'), '[]');
   ```

## 执行

1. 暂停应用写入或安排低流量维护窗口，避免执行合同约束迁移时并发写入合同。
2. 使用有目标 schema 所需权限的 PostgreSQL 客户端连接目标数据库。
3. 依次执行上方三个 SQL 文件。每一步检查客户端退出码和错误输出；任何一步失败就停止，不要继续后续脚本。
4. 保存迁移输出和执行时间，恢复应用服务后查看启动日志与数据库连接状态。

例如在已安全设置连接环境的终端中：

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f backend/app/migrations/2026_10_site_electricity_difference_split.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f backend/app/migrations/2026_10_contract_period_constraints.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f backend/app/migrations/2026_10_meter_brand_contract_link.sql
```

## 执行后验收

检查以下结构和数据：

```sql
SELECT column_name
FROM information_schema.columns
WHERE table_name = 'landlord_monthly_elec'
  AND column_name IN ('shared_unallocated_kwh', 'shared_unallocated_amount');

SELECT conname
FROM pg_constraint
WHERE conrelid = 'contracts'::regclass
  AND conname = 'ex_contract_no_overlap';

SELECT table_name, column_name
FROM information_schema.columns
WHERE (table_name = 'meters' AND column_name = 'brand_contract_id')
   OR (table_name = 'meter_shared_allocations' AND column_name = 'brand_contract_id');
```

然后在应用中抽查：

- 同一场地连续但不重叠的合同可保存；同一计价对象时间重叠的合同会被拒绝。
- 同场地同品牌只有一份品牌合同时，电表/共享分摊合同关联已自动填入；存在多份合同时关联保持空白，可手动选到正确合同。
- 选合同后电费使用该合同费率；跨场地、跨品牌或账期无效的合同不能关联。
- 电费台账的场地损耗与共享表未分摊量分开展示。
- 普通财务、受限类别财务和只读股东账号分别按权限验收。

确认业务抽查无误后，记录迁移版本、数据库环境、执行时间、结果和抽查账期。迁移前后的关键账单金额应留档比较。

## 失败与恢复

- 脚本执行报错时停止后续步骤并保留完整错误输出；先确认失败语句是否已部分生效，再决定修复后重跑。不能假设整个多语句文件总是自动回滚。
- 合同约束迁移因历史重叠合同失败时，按预检结果修正合同日期/提前终止日期，再重新备份并执行该迁移。
- 若无法确认数据一致性，停止应用写入并从执行前备份恢复到新数据库或按既定灾备流程恢复。不要用未经验证的反向 SQL 删除约束、清空关联字段或覆盖历史账单。
- 回滚恢复后将应用版本与数据库恢复到同一发布点，并重新执行只读验收。
