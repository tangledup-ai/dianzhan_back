# 主体归属模型速查（2026-09 确定口径）

> **改任何涉及"公司主体/报税主体/收付款主体"的代码前，必读本文档。**
> 口径由用户于 2026-09-05/06 确认，违反口径的改动会造成页面数字对不上。

## 一、核心原则

**报税主体以电表为准。**

- `meters.entity_id` 是主体归属的**唯一真相**（一块电表同一时间只归属一个主体，`entity_source` 标记 manual=手动指定 / auto=跟随场地合同）；
- **品牌方合同不携带主体**：表单无选择器、保存置 null、Excel 导入强制 null；
- **场地合同保留**"收付款主体"选择器：它是场地成本的付款方，也是**电表未手动指定主体时的默认继承来源**（`_venue_entity_id`：该场地方最新一份场地合同的主体）；
- 电表换主体 = 直接替换（单列），无需先解除关联。

## 二、统一归属链

所有"XX 归属哪个主体"的展示/计算，按以下链路取值（已统一实现的口径）：

```
合同/配置上显式指定的主体
  → 电表的主体（收入按「场地+品牌」的电表柜数加权，成本按「场地」的电表柜数加权）
    → 都没有 = 「未指定主体」（能归属就显示，归属不了的集中到待归属/未指定分组，绝不静默丢弃）
```

- 权重口径：每块计费电表按 `GREATEST(1, 柜子数)` 计（与分红/合同列表一致），排除 TEST 前缀电表；共享电表（brand_id 空、tag=共享电表）单列。
- 已实现此口径的位置：合同页分组、公司主体页场租视图、主体损益表（entity_monthly）、首页明细（monthly_detail）、场租页（rent，含年度行）、股东页看板（station_board）、预警分组（alerts）。

## 三、各页面展示层级

| 页面 | 层级 | 拆分行为 |
|---|---|---|
| 合同管理 | 主体 → 场地方 → 合同 | 同场地同品牌电表分属多主体时，品牌合同**按柜数比例拆到各主体名下**各显示一行，标注"（分摊 x%）"，金额按比例折算；场地方可同时出现在多个主体名下 |
| 公司主体（场租视图） | 主体 → 场地方 → 合同 | 同上；无主体合同集中在"未指定主体（待归属）"分组 |
| 场租台账 | 行级 entityName 标签 | 归属链取标签；年度付款计划同 |
| 主体损益表 / 首页明细 | 主体 → 明细 | 按柜数分摊（含尾差校正，保证合计闭合） |
| 股东分红 / 预警 | 场地方按主体分块 | 归属链取标签 |

## 四、收入与成本的归属差异

- **收入（品牌方合同租金 + 电费收款）**：电费按台账行自带的 entity_id（源自电表）；品牌租金无主体时按该场地该品牌电表柜数**分摊**。
- **成本（场地合同租金 + 电费付款 + 运营费）**：场地合同选了主体 → 整份归它；没选 → 按场地电表柜数分摊；运营费同理（可按主体录入）。
- **分红基数（股东/介绍人配置，2026-09-06 确认）**：绑定品牌 → 该品牌的收入/利润（该品牌当月无在期合同/电表则基数为 0，本期不参与）；绑定主体（未绑品牌）→ 该主体的收入/利润；均未绑定 → 整场地。季/半年/年分红金额 = **周期内各月逐月累加** × 比例（非"结算月当月×倍数"），每月构成通过 `cycleDetail` 返回；非结算月金额为 0。
- **注意**：主体系"报税归属"口径，与实际收付款账户可能不同——系统数字按报税口径算。

## 五、修改时的常见坑（历史上踩过）

1. **不要**在品牌方合同上加回主体选择器或按合同 entity_id 独占归属——会绕过按柜数分摊（contracts.py 导入、overview 旧分支都因此改掉）。
2. **不要**用 `MAX(entity_name)` 之类跨优先级聚合取主体——必须按优先级（场地合同 > 其他合同 > 电表）取，参考 station_board 的 `DISTINCT ON ... ORDER BY pri`。
3. **不要**把"未指定主体"分组直接丢掉——它是待办信号（电表还没关联主体），应集中展示。
4. SQL 里 `LIKE 'TEST%'` 在带参数执行时要写成 `TEST%%`（psycopg2 占位符转义），否则 IndexError。
5. 涉及分摊的列表：一个场地方/一份合同可能出现在**多个**主体名下（各带比例），合计按各自分摊额计算，不要按"合同数 × 全额"重复累加。
6. 分红明细（dividend_shares）重建时必须带 `entityId`（dividend_refresh 已修，新建路径 dividends.py 一直有）。
