## 目标

在「基础档案 → 平台人员」中可为财务/财务主管指定**电表类型数据范围**(全部/合作商电表/民用电表/共享电表)。指定后该账号登录整个系统,所有页面只能看到该类型电表相关的数据;未指定的账号不受影响。已确认的规则:
- 范围内数据**可编辑**,跨范围读写一律被后端拒绝
- 合同/场租/总览等**场地级**数据:场地拥有该类型电表即整场可见(电表列表仍只显示该类型)
- 范围选项含「共享电表」;仅对财务/财务主管生效(老板恒为全部,股东沿用现有场地隔离)

## 实现步骤

### 1. 数据库(2 个文件)
- `backend/app/database_init.sql`:platform_users 建表语句加 `meter_tag_scope VARCHAR(20)`,并按现有惯例补 `ALTER TABLE platform_users ADD COLUMN IF NOT EXISTS meter_tag_scope VARCHAR(20);` + COMMENT(存量库自动升级)
- 新增迁移记录 `backend/app/migrations/2026_09_platform_user_meter_tag_scope.sql`

### 2. 隔离核心 `backend/app/infra/auth_scope.py`
- 新增 `scope_meter_tag(request)`:读 `request.state.current_user.meter_tag_scope`,合法值返回该 tag,否则 None;boss 角色强制 None
- 扩展 `scope_landlord_ids(request)`:财务类角色若设了范围,返回 `SELECT DISTINCT landlord_id FROM meters WHERE tag = 范围 AND landlord_id IS NOT NULL`(场地级派生);否则维持现状
- **效果**:电费台账、场租、合同、分红、经营总览、场地看板、目录场地方列表等已消费 `scope_landlord_ids` 的约 8 个文件自动获得隔离,无需逐个修改

### 3. 电表维度过滤(防止按 meterNo 枚举绕过)
- `meter_repo.list_meters` 加 `allowed_tag` 参数(`AND m.tag = %s`)
- `backend/app/api/meters.py`:列表传 tag 范围;`GET /{id}` 范围外返回 404;POST/PUT/DELETE 校验目标电表(含改归属/改类型后的落点)在范围内,越界 403
- `backend/app/api/meter_energy.py`:daily/hourly/monthly 三个查询已 join meters,补 `m.landlord_id = ANY(...) AND m.tag = ...`;`POST /readings` 校验 address 在范围内
- `backend/app/api/electricity.py` `GET /reading-detail`:按电表范围过滤抄表明细
- `backend/app/api/alerts.py`:电量异常预警 SQL(join meters 处)按 tag/场地过滤
- `backend/app/api/cabinets.py`:GET join meters 过滤,写操作校验所属电表在范围内
- `backend/app/main.py` `GET /api/meter-monthly`:join meters 同样过滤

### 4. 平台人员管理 API
- `backend/app/repositories/directory_repo.py`:create/update_platform_user 增加 `meter_tag_scope` 参数(update 支持显式清空)
- `backend/app/api/directory.py`:platform-users POST/PUT 接收 `meterTagScope`,校验取值合法
- `backend/app/api/auth.py` `_user_payload` 增加 `meterTagScope`(登录/`/auth/me` 均返回;中间件 `SELECT *` 自动带出,改范围即时生效无需重发 token)

### 5. 前端
- `src/api/auth.ts`:`AuthUser` 加 `meterTagScope?: string | null`;`src/api/directory.ts` payload 加字段
- `src/pages/Directory.tsx`(PlatformUsersTable):新增「数据范围」列;财务/财务主管角色显示下拉(全部/合作商电表/民用电表/共享电表),其他角色显示「-」;新增/编辑/导出均带上该字段
- `src/pages/Meters.tsx`:当前用户有范围时,tag 筛选与表单中类型下拉锁定为该值
- `src/components/Layout.tsx`:顶栏用户名旁显示范围徽章(如「合作商电表」),让受限账号明确自己的可见范围

### 6. 验证
- 后端 Python 语法/启动检查,前端 `tsc` 构建通过
- 手动验证:建「只看合作商电表」财务账号登录,核对电表/电费台账/合同/总览/预警等页面只出现该类型相关数据;跨范围直连 API(按 meterNo 查读数、改电表归属)返回 403/404

### 说明(现有业务规则的边界)
- 民用电表按现有业务规则本就不参与电费台账计算(仅合作商+共享电表参与),民用电表范围的账号在电费台账页看到的是其场地下按现有规则生成的台账
- 未关联场地的电表不派生场地范围,只有未限定范围的账号可见(与现有股东隔离行为一致)
